# Xquik 批量采集

2026-09-08 切换为 `xquik/x-tweet-scraper`，没有执行新的真实付费采集。Token 继续由服务端解密使用。

后台来源选择“X 作者组”，填写 2–100 个不同用户名，以逗号、空格或换行分隔。系统去除 @、按大小写去重并验证用户名；每 20 位拼成一条 OR 查询。100 位作者产生 5 条查询，全部放入一个 Actor 运行，`maxItems` 为整批上限，不按作者分别请求。支持免费预览实际输入。

```json
{
  "mode": "search",
  "searchTerms": ["(from:NASAHubble OR from:NASAWebb) filter:images since:2026-09-01"],
  "queryType": "Latest",
  "outputVariant": "rich",
  "fieldStyle": "camelCase",
  "maxItems": 100,
  "includeSearchTerms": true
}
```

日期由服务端生成：首次回溯 7 天，后续成功水位重叠 1 天。保留关键词来源。此版采用 OR 查询方案，未增加 X List 配置入口。

按 [官方说明](https://apify.com/xquik/x-tweet-scraper)，所有 Apify 计划的结果费为 $0.00015 / 条，100 条约 $0.015；Apify 平台用量另计。没有单独启动费、查询费或旧 Actor 的最低 50 条收费。后台估算不是总费用硬上限，实际以账单为准。图片清晰度筛选在本地导入阶段执行，不能退回已交付结果的费用。

新来源默认暂停、每 168 小时、整批最多 100 条。正式库预设 6 位作者的暂停合集，旧单账号来源保留供历史追溯并禁止新任务。已有采集记录保留原 Actor 名称，重启核对使用对应历史 Actor。全局串行、两次启动至少间隔 5 分钟；新运行设置 300 秒超时，避免无限运行。

读取 Xquik `run-report`，出现部分失败、截止时间或分页安全上限时，保存可用图片并标记部分失败，不推进水位。报告读取失败时保留任务以便重试读取，不重新启动 Actor。失败条目重试只处理已有 Dataset 和本地图片。

验证：Go 单元及隔离 schema 集成测试覆盖 100 作者批量输入、多图解析、去重、分页、限流、重启核对及部分报告水位；前端生产构建和 5 个 Playwright 测试通过（1440、1024、390 px，导航、管理、100 作者查询预览、取消付费操作）。真实 Xquik 采集结果和账单尚未验证。
